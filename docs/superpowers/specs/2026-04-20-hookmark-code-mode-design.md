# Hookmark Code-Mode MCP — Design Spec

**Date:** 2026-04-20
**Branch:** `feat/code-mode-mcp`
**Status:** Design approved, pending implementation plan

## Goal

Replace `hookmark-mcp`'s current surface (7 concrete stdio tools wrapping the `hook` CLI) with a code-mode MCP server that exposes the same CLI through the 9-tool code-mode surface used by Brandjet and `attio-remote-mcp-code-mode`. This lets the model chain multiple hook commands in one `call_tool_chain` invocation and makes the server self-describing via OpenAPI.

## Reference Pattern

- `attio-remote-mcp-code-mode/docs/plans/2026-04-15-attio-remote-code-mode.md` — the plan this design adapts
- `brandjet` repo — the shipped reference implementation (`src/index.ts`, `src/manualBuilder.ts`, `src/changelog.ts`)

## Non-Goals

- **No OAuth.** Hook is a local CLI; no tokens, no refresh, no session IDs, no SSE parsing.
- **No remote MCP forwarding.** There is no upstream MCP to proxy. The bridge invokes the local CLI directly.
- **No live `tools/list` sync.** The hook command set is fixed per installed CLI version; the spec is regenerated by a build-time script, not at server startup.
- **No backwards compatibility** with the existing `hookmark_*` tool names. This is a v0.1.0 → v0.2.0 breaking change.

## Components

Each component lives in its own file with a narrow responsibility. Files stay small so the whole server is easy to hold in context.

### `src/hookCli.ts`
Pure wrapper around the `hook` binary. Exports:
- `resolveHookPath(env): string` — reads `HOOK_CLI` env var, falls back to the default homebrew path.
- `runHook(args: string[]): string` — `execSync` with stdout captured, stderr surfaced in thrown Error.
- `shellEscape(s: string): string` — single-quote wrapping with embedded-quote escape.
- `extractHookUrl(text: string): string | null` — regex match for `hook://…`.

Equivalent to Brandjet's `brandjetMcpClient.ts` and Attio's `attioMcpClient.ts`, minus all the remote-protocol machinery.

### `src/manualBuilder.ts`
Builds the OpenAPI 3.0.3 document served at `GET /openapi`. Exports:
- `loadHookCliSpec(): HookCliSpec` — reads `docs/reference/hook-cli-spec.json`.
- `generateOpenApiSpec(baseUrl, spec): OpenApiDocument` — emits `paths[/<operationId>].post` entries with `requestBody` JSON schemas derived from each subcommand's flags/args.
- Operation IDs are the bare hook subcommand names: `clip`, `link`, `list`, `find`, `remove`, `clone`, `from`. These already contain no hyphens, so no normalization (unlike Attio's `search-records` → `search_records`) is needed. Model-facing calls look like `hook.clip({item})`, `hook.link({item_a, item_b})`, etc.

### `src/bridge.ts`
Node `http.createServer`. Responsibilities:
- Route `GET /openapi` → JSON from `manualBuilder`.
- Route `GET /changelog` → HTML from `changelog`.
- Route `POST /<operationId>` → parse JSON body, translate to argv array, call `hookCli.runHook(...)`, return JSON `{ output: string }` or `{ error: string }` with 500.
- Listen on 127.0.0.1 only; port from `HOOK_BRIDGE_PORT` (default 3801).

### `scripts/regen_hook_spec.ts`
Walks each subcommand (`clip`, `link`, `list`, `find`, `remove`, `clone`, `from`), runs `hook help <subcmd>`, parses the help output into a structured description + flag list + positional-arg list, and writes `docs/reference/hook-cli-spec.json`.

**Runs automatically on every server startup/restart.** The checked-in spec file acts as a cache that auto-refreshes against the currently installed Hookmark CLI. Also exposed as `npm run regen-spec` for manual invocation.

Startup behavior:
1. Run regen against the local `hook` binary (~200–500ms for 7 subcommands).
2. If the freshly generated spec differs from the existing `docs/reference/hook-cli-spec.json`, write the new version and trigger the changelog flow (see below).
3. If the `hook` binary is missing or regen fails, log a warning to stderr and fall back to the existing checked-in spec. Server still starts.
4. Opt-out: `HOOK_SKIP_REGEN=1` skips regen entirely (useful for CI and tests).

### `src/changelog.ts`
Ported from Brandjet. Diffs the current `hook-cli-spec.json` against the previous version (stored alongside as `hook-cli-spec.previous.json`) and renders an HTML summary (added/removed commands, added/removed flags, description changes). Surfaced at `GET /changelog` on the bridge.

**Auto-opens in the default browser** via `open <url>` (macOS) in two cases:
1. **Update detected at startup** — regen found a diff, the changelog HTML has new content, browser launches automatically so the user sees what changed in their installed Hookmark CLI.
2. **`changelog` meta-tool invoked** — whether called by the model via MCP or manually by the developer, the tool responds with the bridge URL *and* opens it in the browser.

Opt-out: `HOOK_CHANGELOG_AUTO_OPEN=0` suppresses the browser launch in both cases (for CI and headless runs). The bridge route still serves the HTML regardless.

### `src/index.ts`
Slim orchestrator (~100 lines target). Responsibilities:
1. Redirect `console.log`/`console.warn` to stderr (stdout is JSON-RPC transport).
2. Load `.env` via `@utcp/dotenv-loader`.
3. **Run `regen_hook_spec` against the local `hook` CLI** (unless `HOOK_SKIP_REGEN=1`). If a diff is produced, promote the old spec to `hook-cli-spec.previous.json` and trigger the changelog auto-open flow.
4. Construct `CodeModeUtcpClient` from `@utcp/code-mode` with the HTTP plugin.
5. Start the bridge server; register the generated OpenAPI as manual name `hook`.
6. Register the 9 code-mode meta-tools on the `McpServer`.
7. Connect to `StdioServerTransport`.

## Exposed Tools (9 meta-tools, pure code-mode)

Identical set, names, and order to Brandjet and Attio:

1. `register_manual`
2. `deregister_manual`
3. `search_tools`
4. `list_tools`
5. `changelog`
6. `tools_info`
7. `get_all_tool_interfaces`
8. `get_required_keys_for_tool`
9. `call_tool_chain`

The existing `hookmark_link`, `hookmark_connect`, `hookmark_list`, `hookmark_search`, `hookmark_remove`, `hookmark_clone`, `hookmark_frontmost` tools are **removed**.

## Usage Guide (server `instructions`)

Teach the model to call hook subcommands through the manual:

```
Start with search_tools or list_tools to discover the hook manual.
Use call_tool_chain with a JS body that invokes hook.<subcommand>(args):
  return await hook.clip({ item: "/path/to/file" });
  return await hook.link({ item_a: "/a", item_b: "/b" });
Batch related work in a single call_tool_chain execution.
```

## Configuration

| Env var                    | Default                                             | Purpose                                         |
|----------------------------|-----------------------------------------------------|-------------------------------------------------|
| `HOOK_CLI`                 | `/opt/homebrew/lib/ruby/gems/4.0.0/bin/hook`        | Path to the `hook` binary                       |
| `HOOK_BRIDGE_PORT`         | `3801`                                              | Local bridge HTTP port                          |
| `HOOK_SKIP_REGEN`          | _(unset)_                                           | `1` to skip auto-regen on startup (CI/tests)    |
| `HOOK_CHANGELOG_AUTO_OPEN` | _(unset, treated as on)_                            | `0` to suppress auto-opening the changelog URL  |

`.env` is loaded but optional.

## Testing

TDD task structure (test → implement → commit) matching the Attio plan. Unit tests per component:

- `tests/hookCli.test.ts` — `shellEscape`, `extractHookUrl`, argv construction (mock `execSync`).
- `tests/manualBuilder.test.ts` — spec generation for a small fixture; verify operationIds and request body schemas.
- `tests/bridge.test.ts` — hit the HTTP bridge in-process, assert routing and error shape (mock `runHook`).
- `tests/server-surface.test.ts` — assert the 9 meta-tool names are exported.

No live smoke test against the real Hookmark app (the CI machine won't have Hookmark installed). `scripts/regen_hook_spec.ts` is run manually on the developer's Mac.

## Breaking Change

Package version: `0.1.0` → `0.2.0`.
Removed tools: `hookmark_link`, `hookmark_connect`, `hookmark_list`, `hookmark_search`, `hookmark_remove`, `hookmark_clone`, `hookmark_frontmost`.
Callers that referenced these by name will stop working. README gets a migration note with a `call_tool_chain` example showing the equivalent call.
